# Report export and Outlook email

Use for one-off report delivery. Export from PowerOffice, then email through **Outlook on the web in the same authenticated Chrome profile**. This is the common Windows/macOS workflow. Use the signed-in user's mailbox; do not depend on native Outlook, AppleScript, COM, a fixed owner address, a browser profile name, or an operating-system-specific path. Do not silently send through PowerOffice's native `Email/E-post`, Gmail, or another service.

On 2026-09-28, a live check confirmed `Menu → Reports → Profit and Loss → Share`, including PowerOffice's native email dialog, which was cancelled without sending. It did not validate file download, Outlook attachment upload or a completed send on either platform. Confirm current export controls and tool capabilities at runtime; this procedure is not proof of live end-to-end delivery.

## Resolve the request

Ground five items: company, report type, period/as-of date, optional customer/project filter, and output/destination. Reuse a visibly open report and its selected parameters when the user says “this report.” “Selected client” refers to the company in the client selector unless the request and selected customer row establish customer scope. If multiple interpretations remain, ask one concise clarification before changing scope or sending.

Use the exact full email address supplied by the user or an unambiguous authorized contact already verified in this session. Resolve “send to me” from the requesting user's verified Outlook mailbox or contact; the signed-in mailbox is sufficient only when it is established as that user's. Never infer an address from a display name, a previous administrator, an example or an owner-specific default. Autocomplete is a candidate, not proof. Resolve a missing report type or accounting period before choosing the report. A missing recipient blocks sending only; prepare the scoped report while resolving the address. Previously approved workflow defaults apply only when explicitly established for the current user and workflow.

## Export the report

1. Verify the active company. If another company is named, open the client selector beside the menu, search by exact name/organization number where supported, select the match, and verify the new context. Do not add a client.
2. Stay in the intended report when already open. Otherwise use `Menu/Meny → Reports/Rapporter` and the requested report. Examples are `Profit and Loss/Resultatregnskap` for company profit/loss and `Customer Ledger/Kundereskontro` for customer ledger evidence. In the latter, verify the customer number and whether the request needs `Åpne poster` (open items) or `Kontoutskrift` (account statement). These have different bases; do not substitute one silently.
3. Apply the requested period and relevant filters once. Wait for the updated report and verify heading, parameter summary, customer when relevant, and a control total/count where exposed. Use visible parameters as evidence; reopen settings only if hidden or inconsistent. Profit/loss cannot span accounting years: prepare separate requested-year reports or clarify a requested cross-year presentation.
4. Use the report's `Share/Del` sharing/export control and choose the requested PDF, Excel or CSV format. Preserve the complete requested report. Excel/CSV may include all available columns, so verify scope/privacy rather than assuming hidden columns are excluded. For email without a requested file format, use a suitable full report export, normally PDF for a financial statement.
5. Observe export/download completion and obtain the actual file location from the current browser/tool runtime. Verify the file's identity, format, report scope and content using supported tools. Never invent a path or assume Downloads is in the same place on Windows and macOS. Read the active browser tool's download/upload documentation when needed; only use capabilities and accessible paths it actually supports.

When no file/attachment was requested and the body preserves the complete requested report and its context, skip export/download/upload and compose that complete report in Outlook. A summary or partial table does not replace a requested financial PDF, workbook or other file.

## Send through Outlook on the web

1. Reuse an existing authenticated Outlook web tab in the same Chrome profile first. If none is available, follow the Microsoft 365 app launcher's Outlook link or open `https://outlook.office.com/` for standard Microsoft 365. Preserve a known tenant/cloud-specific Outlook address. Verify the signed-in mailbox and sender; do not switch to an owner-specific account or profile. Missing Outlook access or required sign-in is a concrete blocker or human authentication step.
2. Select `New mail/Ny e-post` using current page evidence. Enter the exact recipient and verify the resolved recipient chip's full address. Remove unrelated prefilled recipients. Use a concise subject and body identifying report, company/customer and period; do not invent personal data or promises.
3. For file delivery, attach the actual verified export through the active browser tool's supported file-upload mechanism. Follow that tool's current runtime restrictions, including platform-specific file access limits. Verify the correct filename and completed attachment state in Outlook; inspect its preview/content when available to corroborate report identity. A filename typed into the body or file picker is not proof of an attachment. For an eligible body-only report, verify that the complete requested content is present instead.
4. Before sending, verify the sender, full recipient address(es), subject, report/company/customer/period, and every required attachment. If a required attachment cannot be accessed or uploaded, stop before sending and state the exact missing capability and the export's observed status/location if available. Do not claim a phantom attachment, substitute a public link, silently switch mail services or replace a required file with a partial body report.
5. With an explicit matching send request, select Send once without asking for redundant confirmation. Observe the result, then open `Sent Items/Sendte elementer` and verify the newly sent message by recipient, subject, timing and attachment(s). If Sent Items cannot be confirmed, report the acknowledgement and the verification limitation. A Sent Items record supports “sent through Outlook”; it does not prove inbox delivery.

If sending times out or the result is ambiguous, inspect Sent Items, Drafts, Outbox when exposed, and any error before deciding whether it submitted. Do not automatically resend. Retry at most once only when evidence establishes that no submission occurred; otherwise report the uncertain outcome.
